平台設定

備份／還原本次編輯的所有資料，並可修改自己的登入密碼

本頁面會自動把登記資料儲存在您目前使用的瀏覽器裡，重新整理網頁或關掉再打開都不會遺失；但僅限「這一台電腦、這一個瀏覽器」，換裝置、換瀏覽器、或清除瀏覽器資料都不會帶過去，建議仍定期按「匯出資料備份」另外保存一份。若要清空本機儲存、換回範例資料重新開始，可按「清除本機自動儲存資料」。

「清空本場次登記資料」跟上面兩個按鈕不一樣：會把雲端資料庫裡「目前這個場次」的所有登記資料整批刪除，所有志工、所有裝置都會一起變成清空（不是只有這台電腦看到的清空），且無法復原——「匯入資料備份（還原）」不會刪掉雲端已有、但備份檔裡沒有的登記資料，若只是想清掉測試用的報名資料，請直接用這顆按鈕，不要靠匯入一份清空過的備份。

雲端同步狀態：尚未設定雲端資料庫（僅使用本機儲存）

請將 Firebase 主控台「專案設定 → 一般 → 您的應用程式 → SDK 設定與程式碼片段」裡的整段設定內容（const firebaseConfig = { ... }）貼在下方，可以整段貼上，不用自己整理成 JSON。

若再發生「新增或刪除報名資料，過一下子又跳回原本舊資料」的情形，請先不要重新整理頁面，直接按下方「複製紀錄」，把內容傳給協助排查的人——這裡會記錄剛才每一筆資料寫入雲端的結果、以及每次從雲端收到更新的時間點，能直接看出問題發生在哪一步。紀錄只留在這次瀏覽器分頁的記憶體中，重新整理頁面就會清空。

此環境目前無法直接下載檔案，請改按「複製到剪貼簿」，貼到記事本／文字編輯器存成 .json 檔即為備份。

若複製失敗，請點一下文字框後按 Ctrl/Cmd+A 全選、Ctrl/Cmd+C 複製

把之前「匯出資料備份」複製出來的 JSON 內容，整段貼到下方文字框，再按「還原這份備份」。

您在後台編輯的場次、品項、費用、報名清單與圖片，僅暫存於本次瀏覽器分頁的記憶體中（本平台目前尚未串接雲端資料庫，重新整理頁面即會清空）。建議編輯告一段落後按「匯出資料備份」保存內容；下次要接續編輯或發布新版網頁時，用「匯入資料備份」貼回來還原，就能確保編輯好的內容不會不見。管理密碼僅為前台簡易鎖定，並非真正的伺服器驗證，請勿用於保護機密資料。

供品品項管理

每個場次的品項與數量都不同，可直接在此新增／修改／刪除

「項次」可直接作為快速登記與 LINE 訊息貼上的辨識關鍵字（例如輸入「3」即比對到 3 號品項）；修改「單價」「總量」「已贊助基準」會立即反映到「剩餘名額總覽」與關鍵字比對，「已贊助基準」是開放報名前既有的預訂數量，之後志工登記會在此基礎上累加。「總量」填 0 或留空代表這項供品不限量，畫面會顯示「不限量」，不會出現已額滿，登記時也不會被擋。

項次品項名稱規格說明單位單價總量已贊助基準剩餘不公開補運欄操作

可先「匯出供品資料」下載 Excel（或複製文字），依上一場法會的品項與數量修改後，用「匯入還原供品資料」貼回或選擇檔案上傳，快速套用到目前這個場次——匯入會直接取代目前場次的整份品項清單（原本的品項與剩餘名額對照就不會保留），請確認場次選對、內容無誤後再匯入。

LINE 訊息貼上快速登記

貼上多筆 LINE 留言，系統嘗試解析姓名、品項與數量，確認無誤後再匯入

建議格式（最不會辨識錯誤）：每行一筆，用逗號分隔「姓名,項次或品項,數量」，例如：
王張牡丹,4,10 陳小姐,壽桃,2 黃姐,12,500
各師尊大壽金要寫敬致的仙佛／師尊時，用 4 欄「姓名,項次,仙佛名稱,數量」，例如： 王小明,17,觀世音菩薩,1
項次可填數字（比對「項次」欄）或品項名稱都可以。只要整段貼上的內容「每一行都有逗號分隔成2～4欄」，系統就會優先用這個方式解析，最準確、最不會有辨識落差。若沒有逗號，系統仍會嘗試辨識「供品項次：」「贊助數量：」「贊助者姓名：」標籤格式，或「陳小姐 壽桃 2」這種舊格式，但正確率不如逗號格式。解析結果請務必核對後再匯入。

版本紀錄

匯出贊助供品「紅紙」Excel（A3）

依目前場次的報名資料，產生 A3 橫式、直書、可直接印在紅紙上的贊助供品名單。檔案裡有兩個工作表，內容與排版完全一樣、都是 1 張 A3：「紅紙-有格線」和「紅紙-無格線」。所有供品都會列出，還沒人報名的品項留空白格，方便之後自己在 Excel 裡補。

匯出補運A4 Excel

依目前場次有填補運的報名資料，照古亭院補運紅紙工作表的格式產生 A4 直式 Excel，每一頁一張。補運名稱「補運」放在「一戶-全部」（一筆報名一張，多人名字寫在同一張）；「補運+補財庫」放在「個人戶」（每個名字各一張）。地址用補運地址，報名姓名欄有多人時請用「、」或逗號分開。
